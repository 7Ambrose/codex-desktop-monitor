# Codex 桌面任务监控

[下载预览版](https://github.com/7Ambrose/codex-desktop-monitor/releases) · [MIT 许可证](LICENSE)

**本机网页：**安装启动后，双击桌面“Codex 监控”打开带验证的面板，默认地址为 `http://127.0.0.1:17863/`。这是每个人自己电脑上的地址；分享项目请发上方 GitHub 链接。

**Windows 预览版：安装环境、下载步骤、已知限制与分享方法见 [发布说明](RELEASE.md)。提供源码包，需要 Python 3.11+、Node.js 22+、已登录的官方 Codex 和单独安装的 HUD。**

## 组合方案

日常状态与用量显示复用 [Codex Monitor HUD](https://github.com/LH-03/codex-monitor-hud)，本项目补充按需 GPT 复核及操作确认。固定版本、校验值和职责见 [第三方组件说明](THIRD_PARTY.md)。HUD 的暂停只暂停显示更新。

优先速度与省用量：基础监控零模型调用；连续相同失败或手动请求才复核；GPT-6 Luna、低推理、每轮最多一次、间隔至少十分钟、每日最多十次。此模式不会自动发现每一种偏题，重要交付可手动复核。

组合安装后，HUD 使用紧凑汇总条，仅显示任务数、5 小时和周剩余额度。桌面“Codex HUD”打开小浮标，“Codex 监控”打开带验证的详细面板。当前用户的计划任务独立启动隐藏观察进程，每 5 秒检测 Codex 桌面，随桌面开启后台与 HUD，退出稳定 15 秒后关闭它们，每 30 秒检查并恢复丢失的后台或 HUD。不主动打开浏览器；需要详细依据时双击桌面图标即可。已经打开的浏览器标签页不会被强制关闭。首次安装并信任钩子后，重启 Codex 桌面端以加载配置；面板显示“等待任务接入”时，不能认为任务已被监控。登录自启需要下一次实际登录验证，手动启动成功不能替代该验收。

在 Codex 桌面端继续聊天，本机全局 Hook 自动记录所有工作目录下的新对话生命周期事件；独立 GPT 按需检查偏题、重复失败和交付依据。提供中文面板，异常时在下一次工具操作前请求确认。

## 面板里直接执行任务

双击桌面“Codex 监控”，点击“新任务”，填写工作文件夹和任务后发送。模型与权限折叠在输入框上方，默认跟随当前 Codex 的模型和推理强度；也可单独选择模型、推理强度或只读模式。此操作会使用模型额度，监控轮询本身不使用模型。

下方会显示输出与状态。运行时可点击“中断任务”，等待“已中断”后补充要求或点击“继续任务”，沿用同一会话历史。中断不会撤销已经完成的文件修改。需要命令或文件审批时，显示具体内容，由用户允许一次或拒绝；不会自动批准。不支持的交互请求会明确提示，可中断后补充要求继续。

后台复用固定版本的 Supervisor，无额外 npm 依赖；使用官方 CLI 登录。默认限制在已启用文件夹、工作区写入或只读模式，限制任务内命令访问外网；CLI 连接 OpenAI 仍需网络。最多四个执行或待确认启动请求。启动请求去重，中断与继续核对轮次，只允许控制本面板启动的任务。Windows 子进程使用 Job Object，后台退出后不留下脱离监控的受管子进程。重新打开后台后不会自动续跑，需要用户明确继续。

面板任务关闭钩子、应用、插件、记忆与额外 MCP 加载，以减少启动和上下文开销。桌面对话仍保留只读监控与下一步拦截，不能假称已经被本面板接管。

HUD 外观完全跟随 Codex Monitor HUD 自己保存的用户设置。监控后台不会改写颜色、布局、字号或显示字段；后台启动和每三十秒健康检查时，只会在浮标超出显示器工作区时调整它的位置。

## 桌面对话监控的边界

- **操作确认不等于整项任务已中断。** 当前桌面进程没有已验证的外部控制连接；本项目使用官方 MCP Hook 和 elicitation 确认，在下一个工具调用前等待用户。已经启动的命令可能继续运行。
- 在客户端提供确认能力且钩子已受信任时，确认窗口才可用。没有确认能力则明确拒绝该次工具调用，不能宣称整个模型循环已停止。
- Codex 官方 Hooks 对错误和超时可能放行；本项目不是不可绕过的权限或安全隔离系统。监控连接失败时会提示，不能假装仍受保护。
- 确认异常并请求拦截时会尝试发送 Windows 系统通知，同时在面板保留原因；勿扰模式可能隐藏横幅。原聊天的确认弹窗只在受信任的 PreToolUse 钩子遇到下一次操作且客户端支持 elicitation 时出现，不能保证立即弹出或停止已启动的命令。
- 独立 GPT 只审核收到的材料；未读取内容、未渲染的版式和不完整工具结果均不能算验证通过。
- 文件内容检测目前限于输出路径存在性和少量文本摘录。Word、PDF 等只检查文件元数据，尚未接入内容和版式渲染验收。
- 页面中的 CPU 是后台 Python 服务的单核使用率，不包含 Codex 子进程或浏览器。正式占用报告应分别测量这些进程。

## 使用

需要 Python 3.11+ 和可以正常登录的官方 Codex CLI。没有第三方 Python 包依赖。

1. 运行 `python configure.py prepare`，生成本地设置和待审核的安装定义。
2. 检查 `.local/hooks.proposed.json` 与 `.local/config.proposed.toml`。
3. 运行 `python configure.py install`，可逆地合并 MCP 和钩子配置。其他配置会保留，原件备份在 `.local/backup-*`。
4. 双击 `打开监控.cmd`，启动后台并打开本机面板。
5. 按 Codex 官方流程审核并信任新钩子，再在桌面端开始新任务。仅安装配置不代表钩子已信任、已触发或已完成真实任务验收。

Windows 可运行 `install_windows.ps1` 完成安装及隐藏的登录观察项，不会在登录时调用模型。观察项常驻，但无 Codex 桌面时不运行 HUD 或监控服务。

通过 `settings.local.json` 配置工作文件夹、排除的聊天、复核模型和频率。空的 `enabled_roots` 表示尚未启用监控范围。安装程序首次准备时以项目所在父文件夹为默认范围，应按实际需要检查。

卸载定义：`python configure.py uninstall`。该操作只移除本项目的配置段和钩子，保留其他设置与任务文件。自动启动如另行配置，需要同时移除对应启动项。

## 常规监控与提醒

任务卡显示最近活动、事件类型、状态与耗时。提醒中心保留本轮结束、中断、连续三次明确失败，以及运行中长时间没有新事件的提醒；同一事件去重，可标记已读。后台每十秒检查一次，浏览器关闭后仍检查并尝试发 Windows 通知，不调用模型。运行中三分钟没有新事件时，任务卡显示等待进展并发送疑似停滞通知；这可能仍是正常推理或长命令，不代表已确认卡死。阈值可在本地配置调整。

“查看依据”提供最近错误、进展和可折叠的原始事件；“打开原聊天”使用 Codex 的线程深链接，需系统注册相应协议。停滞判断不等于确认卡死，不会自动重启、自动续跑或自动提交指令。安装的全局 Codex Hook 会自动观察之后活跃的桌面对话，不要求逐个手动挂 Hook；不扫描并导入历史会话。Hook 事件和任务摘要保存在本机监控数据库中。

## 独立复核方式

默认通过 `codex exec` 使用官方保存的登录状态，不读取或复制登录令牌，不要求将账号凭据写到项目中。使用临时只读会话、关闭钩子和不必要的工具能力；复核出现工具调用则废弃结果。额外调用会消耗相应模型用量。

默认使用省用量模式：普通回答结束不会调用模型，只有连续相同失败或用户手动请求时复核。默认 GPT-6 Luna、低推理强度、标准速度；GPT-5.6 Luna 是可手动选择的备选，不自动升级到更贵模型。内置较短的专用复核指令替代通用编码指令，并对送审材料限长。

默认每轮最多 1 次、自动复核间隔至少 10 分钟、每天总计最多 10 次（包括手动和失败尝试）。同一聊天只保留一个排队复核，过期结论不能控制新轮次。复核不可用时显示不可用，不能记为通过。可在本地设置中改为 `balanced`（文件交付时复核）或 `comprehensive`（每轮结束复核）。

## 数据与访问

- 数据库、访问令牌、运行日志、模型审核临时文件和安装备份均放在 `.local/`，Git 忽略。
- 个人设置使用 `settings.local.json`，Git 忽略。仓库只包含默认示例。
- HTTP 只监听 `127.0.0.1`，任务数据和控制操作需要本机随机令牌，并核查 Host 和 Origin。
- 默认保留最近 7 天日志；已知密钥格式会被遮盖，但不承诺能识别任意格式的秘密。
- 不从运行日志推测订阅总账或人民币费用。
